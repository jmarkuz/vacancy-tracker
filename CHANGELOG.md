### 2026-11-12 — T-092 review backlog
- F13: the start-up sweep no longer marks a live run as interrupted. A scheduled run can begin before the application is ready; the sweep now touches only runs that began before this process booted. Test: ExpiryAndRunLockTest.

The adapters name the companies they still follow and the expiry skips a vacancy whose company is no longer on the list; a board that is still listed expires as before. Tests: ExpiryAndRunLockTest.
- F7: a source that stalls can no longer hold the run lock. The body of a manual import page is read within 30 s like the collection fetcher's (a page that stalls half way ends with "The page did not arrive in time"), and a run watchdog closes a run that takes longer than `APP_COLLECTION_MAX_RUN_MINUTES` (default 30): the run is marked interrupted, the Refresh stream is told it is over, the stuck thread is interrupted and given up, and the next Refresh starts on a fresh thread. Tests: BodyDeadlineTest, UrlFetcherTest, ExpiryAndRunLockTest.

- T-072: Structured logs with secret masking, and run metrics (ADR-034). - T-071: Access token and login rate limit for the vps profile (ADR-033, ADR-017). With SPRING_PROFILES_ACTIVE=vps every /api request needs APP_ACCESS_TOKEN, as 'Authorization: Bearer' or the vt_token cookie; without it the answer is 401. The static pages, /actuator/health and the auth endpoints stay open. A sign-in page asks for the token once; the server sets an HTTP-only, SameSite=Strict cookie (Secure over HTTPS, 30 days) and the page never stores the token; a lost session (401) returns the user to the sign-in page; there is a Sign out button. The token is compared in constant time, must be at least 16 characters, and the app refuses to start without it in the vps profile. After 5 wrong tokens from one address within 10 minutes the address gets 429 with Retry-After, and even the right token is refused until the wait ends; a correct login clears the failures; requests with no token do not count. The local profile is unchanged and needs no token (GET /api/auth/status says so). 21 backend tests (limiter, token, the vps API: 401, Bearer, cookie, Secure flag, rate limit for login and API, other clients unaffected, logout; local profile) and 7 frontend tests; checked in a real browser against the vps profile: sign-in page, wrong token, lockout message, right token, cookie flags, reload, lost cookie, sign out; curl 401 and 200; the token does not appear in the app log. Limits: the failure table is in memory and per address (many addresses are slowed, not stopped); the cookie holds the token itself; HTTPS must come from the reverse proxy (T-075) and the app must not be reachable except through it; no CSRF token beyond SameSite=Strict; the limit was not tried through a real proxy with X-Forwarded-For.
- T-070: Daily pg_dump backup service (ADR-032). A new backup service in docker-compose.yml (postgres:16 image plus ops/backup/backup.sh) backs up at start and then every BACKUP_INTERVAL_SECONDS (one day) into the backups volume, as <database>-YYYYMMDD-HHMMSS.dump in PostgreSQL's custom format. A dump is written under a temporary name, read back with pg_restore --list, and only then renamed, so a damaged file never looks like a backup; a failure is logged and retried at the next interval. Files older than BACKUP_KEEP_DAYS (14) are deleted, and only files the script made. Restore is documented in the new docs/operations.md and was tried on a real compose stack (data changed after the backup came back as it was). ops/backup/test-backup.sh checks, with a throwaway PostgreSQL in Docker: the file appears, it restores into a fresh database with the same rows, a failed dump leaves nothing and exits non-zero, retention deletes only old backup files. Also ran the real compose service with a 5 second interval: files appeared. Limits: the volume is on the same machine as the database, so copy files off the host yourself; backups run at fixed intervals from container start, not at a set hour; the Docker test is a script run by hand, not part of mvn verify; restore needs the app stopped.
